# 10 — 要求仕様 (GRID_COMPOSITION)

> **Version: v0.2** (v0.1 からの主な変更: UC-09 SetOrder の `order_value` 入力を明示)

## このドキュメントの位置づけ

本書は `GRID_COMPOSITION` Capability に対する **要求仕様** である。

> 「何のために、誰が、何をできる必要があるか」

を記述する。**「どう実装するか」は規定しない**。

実装方針 (クラス構造・フレームワーク選択・UI レイアウト) は AI の判断に委ねる。
人間が固定するのは:

- 解くべき問題 (背景)
- 想定ユーザーとシナリオ
- ユースケース (操作単位)
- 非機能要件
- 用語の意味 (Ubiquitous Language)

> [!NOTE]
> 上位の Capability BOM (`20-capability-bom.md`) と本書を組み合わせて初めて意味が確定する。
> 本書は「何を作るか」、BOM は「どこに意思決定があるか」を担当する。

---

## 1. 背景と目的

### 1.1 解きたい問題

複数の画像を並べて 1 枚の合成画像を作りたいユーザーが、

- 画像を **任意の行 × 列のグリッド** に配置でき
- 1 枚の画像を **複数セルに跨らせる** ことができ
- 配置を **柔軟に編集** (移動・入れ替え・順序変更) でき
- **配置の妥当性** (はみ出し・重複) が保証される

ための機能群を提供する。

### 1.2 GRID_COMPOSITION が担う範囲

`GRID_COMPOSITION` は「**グリッド上にどの画像 (派生物) をどう配置するか**」だけを担う。

担わないもの:

- 画像ファイルの取込・特性編集 (`IMAGE_VARIANT_MANAGEMENT` に委ねる)
- 操作の取消・やり直し (`HISTORY_MANAGEMENT` に委ねる)
- 最終 PNG への描画と出力 (`RENDERING_EXPORT` に委ねる)
- ワークスペース (DB / 画像格納) の切替・保存

> [!IMPORTANT]
> GRID_COMPOSITION は他 Capability と必ず連携する。
> ただし他 Capability の **意思決定** を所有してはならない (詳細は BOM 参照)。

## 2. 想定ユーザーとシナリオ

### 2.1 ペルソナ

| ペルソナ | 特徴 | GRID_COMPOSITION への期待 |
| --- | --- | --- |
| **編集者 (主たる利用者)** | 個人または小規模事業者。資料/SNS/印刷用に複数枚の画像を 1 枚にまとめたい | 直感的に「ここに置く / これを外す / 入れ替える」ができる |
| **再利用者** | 同じ画像を異なるトリミング/配置で何度も使う | 同じ素材を複数の配置として持てる (派生物の概念) |
| **大判出力者** | 不均等なコマ割り (例: メイン大 + サムネ小) を組みたい | 1 つの配置で複数セルを占有でき、行列ごとに重み (比率) を持てる |

### 2.2 ユーザーシナリオ (代表)

#### S1: シンプルな格子配置

ユーザーは 3×3 のグリッドを作成し、9 枚の画像派生物を各セルに 1 枚ずつ配置する。
配置順は後から並べ替えられる。

#### S2: 不均等配置 (大コマ + 小コマ)

ユーザーは 3×3 グリッドの中央 2×2 に 1 枚を配置し、周囲の 5 セルに別画像を配置する。
中央の配置は 2×2 セルを占有する単一の配置物として扱われる。

#### S3: 入れ替え

セル A にある配置とセル B にある配置を入れ替える。
両者の占有サイズが異なる場合、入れ替えが成立しないことがある (Rule で判断)。

#### S4: 移動

配置を別のセルへ移動する。移動先で他の配置と重なる場合は拒否される。

#### S5: 比率変更

ユーザーは列の重みを `[1, 2, 1]` に変更する。グリッドの行列数は変わらないが、
表示比率が変わる。配置位置 (セル座標) は変わらない。

#### S6: 行列ロック

特定の列を「フィット動作で重みを変えない」よう固定する。
これにより一部の列幅を保ったまま他の列だけ自動調整できる。

## 3. ユースケース

> ユースケースは **「ユーザーが起動できる操作単位」**。UI 部品 (ボタン・メニュー) ではない。

### 3.1 一覧

| ID | 名前 | 概要 |
| --- | --- | --- |
| UC-01 | `CreateGridCanvas` | 新しいグリッドキャンバスを作成する (行数・列数・出力サイズ指定) |
| UC-02 | `ChangeGridDimensions` | 既存グリッドの行数・列数を変更する |
| UC-03 | `ChangeRowColumnWeights` | 列または行の重み (比率) を変更する |
| UC-04 | `ToggleRowColumnLock` | 列または行のロック状態を切り替える |
| UC-05 | `PlaceImageCopy` | 画像派生物をグリッドの指定位置に配置する |
| UC-06 | `MovePlacement` | 既存配置を別のセル位置へ移動する |
| UC-07 | `SwapPlacements` | 2 つの配置の位置を入れ替える |
| UC-08 | `ResizePlacementOccupancy` | 配置の占有セル数 (N×M) を変更する |
| UC-09 | `ChangePlacementOrder` | 配置の z-order (重なり順) を変更する |
| UC-10 | `RemovePlacement` | 配置を取り除く |
| UC-11 | `ListPlacements` | グリッド上の配置を順序付きで取得する |

### 3.2 各ユースケースの詳細

#### UC-01: CreateGridCanvas

- **入力**: 名前 / 行数 (≥1) / 列数 (≥1) / 出力サイズ (幅・高さ、px)
- **事前条件**: なし
- **事後条件**: 空のグリッドキャンバスが 1 つ生成される。既定の列重み・行重みは均等 (すべて 1)。既定のロックはすべて未ロック
- **失敗**: 行数 0 以下、列数 0 以下、出力サイズが正でない

#### UC-02: ChangeGridDimensions

- **入力**: 対象グリッド ID / 新しい行数 / 新しい列数
- **事前条件**: 対象グリッドが存在する
- **事後条件**: 行数・列数が更新される
- **失敗**:
  - 新しい寸法で **既存配置が境界外に出る**
  - 新しい寸法で **既存配置同士が重なる** (理論上発生しないが防御的に検証)
- **付帯**: 重み配列の長さは新寸法に合わせて自動調整 (詳細は設計書)

#### UC-03: ChangeRowColumnWeights

- **入力**: 対象軸 (Row | Col) / 新しい重み配列 (要素数 = 行数 or 列数、各要素 > 0 の整数)
- **事前条件**: 対象グリッドが存在する
- **事後条件**: 指定軸の重みが更新される。配置のセル座標は変わらない
- **失敗**: 要素数不一致、重みに 0 以下を含む

#### UC-04: ToggleRowColumnLock

- **入力**: 対象軸 (Row | Col) / インデックス
- **事後条件**: 指定軸の指定インデックスのロック状態が反転する
- **意味**: ロック中の軸は **フィット動作 (自動重み調整)** で対象から除外される

#### UC-05: PlaceImageCopy

- **入力**: 対象グリッド ID / 画像派生物 ID (`CopyId`) / 配置位置 / 占有サイズ
- **事前条件**: 対象グリッドが存在する。画像派生物が存在する
- **事後条件**: 新しい配置が 1 つ生成される。z-order は末尾 (最前面) に追加される
- **失敗**:
  - 配置がグリッド境界を超える (UC では `OutOfBounds`)
  - 配置が既存配置と重なる (`Conflict`)
- **付帯**: 占有サイズの初期値として画像派生物が保持する既定占有サイズを採用してよい (Rule で規定)

#### UC-06: MovePlacement

- **入力**: 配置 ID / 新しい配置位置
- **事後条件**: 配置位置が更新される。占有サイズ・順序は変わらない
- **失敗**: 境界超え、他配置との衝突 (自分自身は衝突対象から除外する)

#### UC-07: SwapPlacements

- **入力**: 配置 ID × 2
- **事後条件**: 2 つの配置の位置が入れ替わる
- **失敗**:
  - 入れ替え後にいずれかが境界を超える
  - 入れ替え後に他の配置と衝突する (相手 2 つは互いに衝突対象から除外)

#### UC-08: ResizePlacementOccupancy

- **入力**: 配置 ID / 新しい占有サイズ
- **事後条件**: 占有サイズが更新される
- **失敗**: 境界超え、他配置との衝突

#### UC-09: ChangePlacementOrder

- **入力**:
  - 配置 ID
  - 操作種別 (BringToFront | SendToBack | MoveForward | MoveBackward | SetOrder)
  - 順序値 `order_value` (整数、**operation == SetOrder のときのみ必須**。他 operation では null / 省略)
- **事後条件**: z-order が更新される。グリッド内の全配置の order が 1..N の連続値で一意 (R-06 + R-09 と同じ規範)
- **失敗**:
  - `NotFound`: 配置が存在しない
  - `InvalidOrderValue`: SetOrder で `order_value` が 1..N の範囲外、または他 operation で `order_value` が指定された

#### UC-10: RemovePlacement

- **入力**: 配置 ID
- **事後条件**: 配置が取り除かれる
- **付帯**: 残った配置の順序は詰める (詳細は設計書)

#### UC-11: ListPlacements

- **入力**: 対象グリッド ID
- **出力**: 配置のリスト (z-order 昇順、Position 順は問わない)
- **失敗**: なし (グリッドが存在しないなら空)

## 4. 非機能要件

### 4.1 整合性

- すべての配置は **常に** `PlacementMustFitWithinGrid` および `PlacementsMustNotOverlap` を満たす
- 不正な状態が DB / 永続化層に書き込まれてはならない (UseCase が拒否する責務)
- 検証は **純粋関数で実施可能** でなければならない (テスト容易性のため)

### 4.2 操作の取り消し可能性

- すべての状態変更系ユースケース (UC-01〜UC-10) は **取り消し可能** でなければならない
- 取り消し操作は別 Capability (`HISTORY_MANAGEMENT`) が担うが、GRID_COMPOSITION は
  - 「変更前の観測可能な状態」を復元できる形で操作を表現すること

### 4.3 永続化

- グリッドキャンバスと配置はワークスペース単位で永続化される
- 永続化の物理形式 (RDB / ファイル / NoSQL) は規定しない
- ただし、配置の **境界保証は永続化後も保たれる** こと

### 4.4 並行性

- 単一ユーザー単一プロセス前提とし、複数同時編集の解決は不要

### 4.5 性能 (目安)

- 1 グリッドあたり配置数 ≤ 100 (1000×1000 グリッドのような病的なケースは扱わない)
- UC-11 (ListPlacements) は対話的応答 (100ms 以内目安)
- UC-05 (PlaceImageCopy) の妥当性検証は配置数 N に対し O(N) で許容

### 4.6 多言語

- 内部表現に言語依存をもたない (表示文字列は外部リソース)
- 規定言語 / 外部表示 は本 Capability の範囲外

## 5. Ubiquitous Language (用語集)

> 本ソフトウェアで一貫して用いる語彙。**実装言語・UI 上の表記とは独立**。

| 用語 | 意味 | 注意 |
| --- | --- | --- |
| **GridCanvas** | グリッドキャンバス。N 行 × M 列のセル格子と最終出力サイズを持つ単位 | 「画像」ではない。配置の入れ物 |
| **Placement** | 配置。グリッド上のあるセル位置に、ある画像派生物を、ある占有サイズで置いたもの | 同じ画像派生物を別グリッドの別セルに配置すると、それぞれ別 Placement |
| **ImageCopy** (画像派生物 / 論理コピー) | 1 枚の元画像から作る「設定違いの使い回し単位」 | **GRID_COMPOSITION の外で定義される。本 Capability は参照のみ** |
| **CellPosition** | 0 ベースのセル座標 `(x, y)` | x = 列方向、y = 行方向 |
| **OccupySize** | 占有セル数 `(width, height)` | width = 列方向、height = 行方向、いずれも ≥ 1 |
| **PlacementOrder** | z-order (重なり順) | 値が大きいほど前面。同値は禁止 |
| **ColWeights / RowWeights** | 列/行の比率。要素数 = 列数/行数 | 正の整数の配列。`[1,2,1]` 等 |
| **ColLocked / RowLocked** | 列/行のロック状態 | フィット動作で重み変動の対象外にする |
| **Fit 動作** | 行数/列数変更時に重みを再配分する自動動作 | ロックされた軸はスキップ |
| **OutOfBounds** | 配置がグリッド境界を超える状態 | UseCase の典型失敗理由 |
| **Conflict** | 配置同士の占有セルが衝突する状態 | UseCase の典型失敗理由 |

### 5.1 用語に関する重要な約束

- **「画像」と呼ばない**: ユーザー視点で「画像を置く」と感じても、システム内部では `ImageCopy` (派生物) を置く。元画像 (`ImageAsset`) を直接配置することはない
- **「セル」は格子の交点ではなく面**: `CellPosition (1, 2)` は「左から 2 列目・上から 3 行目の **マス**」を指す
- **「位置」は左上基準**: 占有サイズが (3, 2) の配置の `Position` は左上のセルを指す

## 6. 受け入れ基準 (この要求仕様への)

この要求仕様は、以下を満たすときに **「AI に渡せる状態」** とみなす。

- [ ] すべてのユースケースに事前/事後/失敗条件が記述されている
- [ ] 用語集に登場する語が、本書内・BOM・設計書で **同一の意味で使われている**
- [ ] 「実装の自由度」と「意味の固定」の境界が明確である (例: UI レイアウトは自由、Rule 名は固定)
- [ ] AI が読んだとき、**「ここで何を決めるべきか分からない」箇所がない**
