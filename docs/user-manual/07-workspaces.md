# §7 ワークスペース

複数のワークスペースを物理的に分離して切り替える機能を解説します。 仕事用 / 趣味用などのアセット混在事故を **タグや検索フィルタではなく DB ファイル単位** で防ぎます。

## 想定ユースケース

| ケース | 推奨構成 |
|---|---|
| **仕事 / 趣味の混在防止** | `work` / `hobby` の 2 ワークスペースに分離。 スクリーン共有時の事故を防ぐ |
| **クライアント別の分離** | `client-a` / `client-b` のように案件単位。 守秘義務契約下のアセット流出防止 |
| **試作と本番の分離** | `production` / `experiment` で安定版と実験版を分ける。 実験版は気軽に削除可能 |
| **テーマ別アーカイブ** | `2025-spring` / `2025-summer` 等、 期間別にアーカイブ |
| **単一ユーザー (混在 OK)** | デフォルトの `Default` 1 つだけ使う |

## 7.20 ワークスペースとは

### 7.20.1 物理分離の意義

タグや単一 DB 内の Project エンティティでは、 フィルタ解除一発で全件露出してしまい、 スクリーン共有や他者画面表示の事故リスクが残ります。 ViewGrid は **DB ファイルそのもの + 画像本体 + サムネを別フォルダに分離** することで、 切替モデルを 「アプリ再起動」 に倒し、 混在を構造的に防ぎます。

### 7.20.2 1 ワークスペース 1 プロセス

ファイルベースのロックにより、 同じワークスペースを 2 つのプロセスから開くことはできません。 二重起動しようとすると **WorkspaceLockedDialog** が表示され、 既存プロセスへ誘導されます。

#### ロックの仕組み

- アプリ起動時、 `workspaces/<name>/viewgrid.lock` ファイルを取得 (排他オープン)
- 同じワークスペースを別プロセスで開こうとするとロック取得失敗 → ダイアログ表示
- 正常終了時はロックを解放、 クラッシュ時もファイル排他は OS が解放する

#### 別ワークスペースは同時起動可能

`work` ワークスペースで起動中でも `hobby` を別プロセスで起動できます (それぞれが別 DB を持つため衝突なし)。

### 7.20.3 ストレージ構造

```
%LocalAppData%\ViewGrid\
├─ active.json              { "name": "work" }
├─ workspaces.json          [{ "name": "work", "displayName": "仕事用" }, ...]
└─ workspaces\
    ├─ Default\             既存ユーザーは自動移行
    │   ├─ viewgrid.db
    │   ├─ images\
    │   └─ thumbnails\
    ├─ work\
    └─ hobby\
```

旧バージョンからアップデートしたユーザーは、 `%LocalAppData%\ViewGrid\viewgrid.db` が `workspaces\Default\` 配下に自動移行されます (アセット / サムネも合わせて移動)。

### 7.21.1 切替

別のワークスペースカードの **切替** ボタン → 確認ダイアログ → アプリ自動再起動。 内部的には `active.json` を書き換えて `Process.Start` + `Application.Shutdown()`。

#### 切替時の挙動

1. **未保存編集の flush**: ドラフトや進行中の保存をすべて完了させる
2. **`active.json` 書き換え**: アクティブワークスペース名を更新
3. **新プロセス起動**: 切替先ワークスペースで ViewGrid を新規起動
4. **現プロセス終了**: 現在のプロセスを自然終了

切替直後は新規起動と同じ挙動なので、 起動オーバーヘッド (1〜2 秒) があります。 頻繁な切替は推奨しません (混在事故防止のため敢えて 「軽く切り替えられない」 設計)。

#### 履歴 / 設定への影響

- **操作履歴**: ワークスペースごとにメモリ保持 → 切替で消える (永続化されないので元のワークスペースに戻っても履歴は復元しない)
- **アプリ設定** (テーマ / 言語 / 既定値): ワークスペース横断で共有 → 切替で変わらない

### 7.21.2 新規作成

ダイアログ下部の **新規ワークスペース** ボタン。 名前と表示名を入力。 名前は英数字+ハイフンのみ (フォルダ名互換性のため)、 表示名は日本語可。

#### 命名規則

| フィールド | 制約 | 例 |
|---|---|---|
| **名前** (フォルダ名) | 英数字 + ハイフン、 先頭 / 末尾はハイフン不可、 1〜32 文字 | `work`, `client-a-2025`, `test` |
| **表示名** | 日本語含む任意の文字、 1〜64 文字 | `仕事用`, `クライアント A 2025年版`, `Production 環境` |

名前は **フォルダ名にそのまま使われる** ため、 後から変更すると DB / 画像ファイルへのパスが壊れます。 ViewGrid ではリネーム時に **表示名のみ変更** され、 名前 (フォルダ名) は不変です。

新規作成は **空のワークスペース** を作ります。 既存からデータをコピーしたい場合は **複製** を使うこと。

### 7.21.3 リネーム

カードのメニュー → リネーム。 表示名を変更 (フォルダ名は触らない設計、 重要)。

### 7.21.4 削除

カードのメニュー → 削除。 即削除ではなく `workspaces\.trash\` に移動 (誤操作対策)。

#### 削除前の確認

確認ダイアログでワークスペース名 (表示名) と中の概算データ量が示されます。 OK を押すと `.trash` への移動が実行され、 元には戻せませんが、 `.trash` フォルダから手動で復元することは可能 (フォルダごと `workspaces\` 直下に移動)。

#### アクティブワークスペースの削除

現在開いているワークスペースを削除しようとすると拒否されます。 先に別のワークスペースへ切替えてから削除してください。

#### 最後の 1 つの削除

ワークスペースが 1 つしかない場合、 削除しようとすると拒否されます。 最低 1 つは残す必要があります (新規作成すれば削除可能に)。

### 7.21.5 複製

カードのメニュー → 複製。 DB / images / thumbnails 全部をコピーして新ワークスペースを作成。

#### 複製の用途

- **本番の安全コピー**: 大きな変更を加える前にスナップショットを取る
- **テンプレ展開**: アセット + バリアント + グリッド一式を持つ 「ひな形」 を複製して案件別に派生させる
- **試作環境**: 「本番」 を複製して `experiment` ワークスペースを作る

複製は同期処理で **データ量に比例した時間** がかかります (画像が多いと数十秒〜数分)。 完了するまで切替できません。

## 7.22 エクスポート / インポート (zip パッケージ)

ワークスペース 1 つを zip にまとめて別 PC / 別ユーザーへ持ち運べます。

### 7.22.1 エクスポート

カードのメニュー → エクスポート → 保存先 zip 指定。 `viewgrid.db` + `images/` + `thumbnails/` を 1 つの zip にパッケージ。

#### zip の中身

```
my-workspace.zip
├── viewgrid.db           SQLite DB (グリッド / 配置 / バリアント / アセットメタ)
├── images/<hash[0..1]>/  画像本体
└── thumbnails/<hash[0..1]>/  サムネ
```

#### 注意

- アクティブワークスペースもエクスポート可能 (DB は read-only オープンされ、 書き込みはロックされる)
- エクスポート中は他の編集操作が一時待機されます
- データ量に比例した時間がかかります (1 GB の画像なら 10〜30 秒程度)

### 7.22.2 インポート

ダイアログ下部の **zip からインポート** ボタン → zip 選択。 新規ワークスペースとして取り込まれます。

#### インポート時のワークスペース名

インポート先のワークスペース名は zip 元の名前 (フォルダ名) と同じ。 既に同名のワークスペースが存在する場合は **重複エラー** で取り込み失敗。 リネーム後にインポートしてください。

#### インポート後

新規ワークスペースとして登録されるだけで、 自動的にアクティブにはなりません。 切替で開いてください。

### 7.22.3 セキュリティ

zip 展開時に以下を防御:
- **zip slip**: パストラバーサル (`../` を含むエントリ) を拒否
- **NTFS ADS**: 代替データストリーム指定を拒否
- 書き出しは `File.Replace` で原子的 (展開中クラッシュでも部分書き込みが残らない)

ただし zip 自体の中身は信頼するため、 **不審な zip のインポートは推奨されません** (取り込まれる画像ファイル自体に悪性のものが含まれる可能性は防げません)。

## 7.23 .trash/ フォルダ

削除されたワークスペースは `%LocalAppData%\ViewGrid\workspaces\.trash\<name>-<timestamp>\` に移動します。 手動で削除可能ですが、 自動削除機能は **未実装** (将来予定)。

### 7.23.1 タイムスタンプサフィックス

`<name>-yyyyMMdd-HHmmss` の形式 (例: `experiment-20260513-153842`)。 同じ名前で複数回削除しても上書きされません。

### 7.23.2 復元

`.trash` 配下のフォルダを `workspaces\` 直下に移動 (リネーム可) すれば復元できます。 復元後、 アプリ起動時に自動検出されるわけではないので、 **手動で `workspaces.json` を編集** して登録するか、 新規ワークスペースとして作成して中身を上書きする必要があります。

### 7.23.3 容量管理

`.trash` は使ったぶんだけディスクを占有し続けます。 ディスク容量を空けたい場合は不要なものを手動削除してください。

## 7.24 起動時のワークスペース解決

ViewGrid 起動時のワークスペース選択フロー:

```
1. %LocalAppData%\ViewGrid\active.json を読む
2. 指定ワークスペースが存在する  → そのワークスペースをアクティブに
   存在しない (削除済み等)        → workspaces.json 先頭をアクティブに
   workspaces.json も空            → Default を自動作成してアクティブに
3. 旧バージョンからの初回起動:
   %LocalAppData%\ViewGrid\viewgrid.db が存在  → workspaces\Default\ に自動移行
4. ロックファイルを取得 → 失敗 → WorkspaceLockedDialog 表示 → 起動中止
5. DI コンテナ構築 + メインウィンドウ表示
```

### 7.24.1 移行が走るケース

- 旧バージョン (workspaces 機能導入前) からのアップデート
- `%LocalAppData%\ViewGrid\viewgrid.db` が手動で置かれているケース

どちらも安全に `workspaces\Default\` 配下へ移動されます (元ファイルは削除)。 移行は 1 回だけ実行され、 以降は `workspaces\` 配下を直接使用します。
