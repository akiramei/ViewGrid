# §1 基本概念

ViewGrid のデータモデルと画面構成を解説します。 以降の章で使われる **アセット / バリアント / グリッド / 配置 / ワークスペース** といった用語の定義をここでまとめます。

> **対応する Quick Start 範囲**: 全章にまたがる前提知識。 まず動かしたい方は [クイックスタート §3](../quickstart.md#3-5-分チュートリアル-最初の-1-枚を出力する) を先に。

## 1.1 データモデル

ViewGrid のデータは以下の階層構造を持ちます。

```
ワークスペース (DB ファイル + 画像 + サムネを物理分離)
├── アセット A  (1 画像ファイル = 1 アセット)
│   ├── バリアント A-1  ← 設定違いの使い回し単位 (共有特性を持つ)
│   │   └── 配置 P1  (どのグリッドのどのセルに置くかを指定)
│   │   └── 配置 P2  (同じバリアントを別グリッドに配置することも可)
│   └── バリアント A-2
│       └── 配置 P3
└── アセット B
    └── バリアント B-1

グリッド G1 (NxM キャンバス) ←── 配置 P1, P3 が所属
グリッド G2                  ←── 配置 P2 が所属
```

- **ワークスペース** — DB / 画像 / サムネを物理的に分離した単位。 仕事用 / 趣味用などの混在事故防止のため
- **アセット** — 取り込んだ画像ファイル (1 ファイル = 1 アセット)
- **バリアント** (論理コピー) — 1 アセットから複数作れる 「特性違いの使い回し単位」。 トリミング / 回転 / 反転などの **共有特性** はここに紐づく
- **配置** — バリアントを特定グリッドの特定セルに置いた実体。 位置 / 占有セル / ピクセル微調整などの **配置固有特性** を持つ
- **グリッド** — 出力単位となる NxM のキャンバス

### エンティティのライフサイクル

| 操作 | 影響範囲 | Undo 可能か |
|---|---|---|
| アセット取り込み | 新規アセット + 既定バリアント 1 件が自動作成 | ❌ (履歴全消去) |
| アセット削除 | アセット + 全バリアント + 全配置が cascade で消える | ❌ (履歴全消去) |
| バリアント作成 | バリアント単体が増える、 配置はゼロから | ❌ (履歴全消去) |
| バリアント削除 | バリアント + そのバリアントを参照する全配置が消える | ❌ (履歴全消去) |
| バリアント分岐 (Fork) | 既存バリアントを複製、 配置 1 件だけ新バリアントに付け替え | ✅ |
| 共有特性編集 | そのバリアントを参照する **全配置の見た目** が変わる | ✅ |
| 配置作成 / 移動 / 削除 | 当該配置のみ | ✅ |
| 配置固有特性編集 | 当該配置のみ | ✅ |
| グリッド作成 / 削除 | 当該グリッド (削除時は所属配置も cascade) | ❌ (履歴全消去) |
| グリッド名 / キャンバスサイズ変更 | グリッドの見た目 | ✅ |
| ワークスペース操作 | プロセス再起動を伴う | ❌ |

「履歴全消去」 の操作は cascade による履歴矛盾を防ぐために、 実行直後に Undo / Redo 履歴をすべてクリアします。 取り戻したい操作は実行前に PNG として書き出しておくとリカバリ可能です。

## 1.2 共有特性 と 配置固有特性

特性は 「バリアント単位で全配置に反映されるもの」 と 「配置単位で個別に持つもの」 の 2 種類があります。

| 種類 | 例 | 影響範囲 |
|---|---|---|
| **共有特性** | スケーリング / 回転 / 反転 / トリミング / 保護領域 | 同じバリアントを参照する全配置 |
| **配置固有特性** | 占有セル (W×H) / ピクセル微調整 (ΔX, ΔY) / 配置位置 | その配置のみ |

→ §5 [共有特性](05-shared-properties.md) / §4 [配置](04-placements.md) で詳述

### 「共有特性を変えると他配置にも影響する」 の意味

例えば photo-001.jpg のバリアント A を 2 つの配置 (P1 / P2) で使い回しているとき:

- バリアント A の **回転を 90°** に変えると → P1 と P2 の見た目が両方変わる (共有特性)
- 配置 P1 の **占有セルを 1×1 → 2×2** に変えると → P1 だけ大きくなる (配置固有特性)

「P1 だけ 90° 回転させたい」 場合は **バリアント分岐 (Fork)** で独立コピーを作ってから回転を変えます。 元バリアントを参照する P2 には影響しません。

→ §4.14 [バリアント分岐 (Fork)](04-placements.md)

- **左ペイン: グリッド一覧** — ワークスペース内の全グリッドをリスト表示。 切替 / 新規作成 / リネーム / 削除
- **中央: キャンバスエリア** — 現在のグリッドを実寸比で表示。 配置 / 移動 / 列・行ハンドル
- **右ペイン: コンテキスト切替** — 何も選択していなければ候補リスト、 配置を選ぶと Inspector、 等

### 1.3.1 ヘッダ

中央キャンバス上部のヘッダには、 グリッド名 / セル数 / キャンバスサイズ表示と、 **プレビュー** / **Export PNG** ボタンが並びます。

### 1.3.2 ステータスバー

ウィンドウ最下部。 左: 現在の状態に応じたヒント / アセット件数 / 未保存バッジ。 右: 履歴サマリ + 履歴 Flyout を開くアイコン。

## 1.4 データの保存場所

ViewGrid はすべてのデータを `%LocalAppData%\ViewGrid\` 配下に保存します。

```
%LocalAppData%\ViewGrid\
├─ active.json              現在アクティブなワークスペース名
├─ workspaces.json          全ワークスペースのリスト
├─ workspaces\
│   └─ <name>\
│      ├─ viewgrid.db       SQLite DB (グリッド / 配置 / バリアント / アセットメタ)
│      ├─ images\           取り込んだ画像本体
│      └─ thumbnails\       サムネキャッシュ (webp)
├─ settings.json            アプリ全体設定 (テーマ / 言語 / アクセント色 等)
└─ logs\                    Serilog ログ
```

設定 (テーマ / 言語) は **ワークスペース横断で共有**。 アセット / 配置 / グリッドは **ワークスペース単位で分離** されます。

→ §7 [ワークスペース](07-workspaces.md) / §10.28 [ファイル場所](10-reference.md)

## 1.5 自動保存と手動保存

ViewGrid は基本的に **編集が即座に DB に永続化** されます (配置の D&D、 リネーム、 削除など)。 ただし右ペイン Inspector / 特性編集タブのように **複数項目をまとめて編集** する画面では、 **保存ボタン** を押すまで反映されません (ドラフト編集方式)。

- ステータスバーに **● 未保存の変更** バッジが出ているときは保存待ち
- アプリ終了時には自動的に flush される

→ §4.10 [Inspector の保存ボタン](04-placements.md) / §9.24 [自動保存設定](09-settings.md)
